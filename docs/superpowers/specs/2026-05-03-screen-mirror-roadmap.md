# Screen Mirror — 产品迭代路线图

基于设计文档 `2026-05-03-screen-mirror-design.md`，按最小可用产品逐步迭代。

---

## v0.1 — 最小可用链路 (macOS → macOS)

**目标**：验证端到端 pipeline 可行性，单平台跑通全链路。

| 模块 | 范围 |
|------|------|
| 发送端 | macOS 全屏捕获 (ScreenCaptureKit) + VideoToolbox H.264 编码 |
| 传输 | RTP/UDP 裸发送，无 FEC，固定码率 |
| 接收端 | macOS 桌面窗口，VideoToolbox 解码 + Metal 渲染 |
| 音频 | 不包含 |
| 配对 | 命令行指定 IP + 端口，无投屏码 |
| UI | 无，命令行启动 |

**验收标准**：
- 发送端捕获 1080p@60fps 画面，接收端窗口内流畅显示
- 端到端延迟 < 100ms（用手机同时拍摄两屏计时）
- 连续运行 10 分钟不崩溃

**预计周期**：2 周

---

## v0.2 — 音频 + 基础传输优化

**目标**：加入音频同步，传输层具备基本容错能力。

| 模块 | 新增/变更 |
|------|----------|
| 音频 | macOS ScreenCaptureKit 音频流 → Opus 编码 → RTP 发送 |
| 接收端音频 | Opus 解码 → CoreAudio 输出 |
| 同步 | RTP Header Extension (RFC 6051) 时间戳 + 音频为主时钟 |
| FEC | Reed-Solomon 固定 10% 冗余 |
| Jitter Buffer | 固定 15ms 视频 / 20ms 音频 (暂不自适应) |

**验收标准**：
- 音视频同步偏差 < 40ms
- 模拟 2% 丢包率下画面不花屏
- 音频无爆音、无卡顿

**预计周期**：2 周

---

## v0.3 — Windows 发送端

**目标**：发送端支持 Windows，验证跨平台 trait 抽象。

| 模块 | 新增/变更 |
|------|----------|
| 捕获 | DXGI Desktop Duplication (windows-capture crate) |
| 编码 | Media Foundation (Intel QSV / NVENC，按硬件自动选择) |
| 音频捕获 | WASAPI Loopback |
| 架构 | 确立 capture/encode trait 抽象，平台实现分 cfg 编译 |

**验收标准**：
- Windows 发送 → macOS 接收，1080p@60fps 流畅
- 编码器自动探测（NVIDIA/Intel/AMD）
- 与 v0.2 macOS 发送端功能对等

**预计周期**：2 周

---

## v0.4 — SPAKE2 安全配对 + mDNS 发现

**目标**：实现投屏码配对流程，替代命令行手动指定 IP。

| 模块 | 新增/变更 |
|------|----------|
| 接收端 | mDNS 注册 "_screenmirror._tcp" 服务 (mdns-sd crate) |
| 发送端 | mDNS 浏览 + 设备列表展示 (命令行 TUI) |
| 配对 | 6 位投屏码 + SPAKE2 密钥交换 (spake2 crate) |
| 控制通道 | TCP 23501，AES-128-GCM 加密 |
| 能力协商 | JSON 格式交换设备能力 |
| 回退 | 手动输入 IP 连接 |

**验收标准**：
- 接收端显示投屏码，发送端输入码后 < 3 秒建立连接
- 错误码 3 次后锁定 60 秒
- mDNS 发现延迟 < 5 秒

**预计周期**：2 周

---

## v0.5 — 系统托盘 UI (发送端)

**目标**：发送端从命令行升级为系统托盘应用。

| 模块 | 新增/变更 |
|------|----------|
| 托盘 | tray-icon + tao 事件循环 |
| 面板 | wry WebView: 投屏码输入 / 设备列表 / 投屏状态 |
| 投屏模式 | 全屏镜像 / 选择窗口 / 自定义区域 |
| 状态显示 | 分辨率、帧率、码率、延迟、丢包率 |
| 操作 | 暂停 / 断开 |

**验收标准**：
- macOS + Windows 均有托盘图标，左键弹出面板
- 选择窗口/区域模式正常工作
- 投屏中状态实时刷新

**预计周期**：2 周

---

## v0.6 — 抢投 + 自适应优化

**目标**：多用户场景支持，传输层智能化。

| 模块 | 新增/变更 |
|------|----------|
| 抢投 | PC 端通知弹窗 + 提示音，10 秒超时让出 |
| 自适应 FEC | 丢包率 → 动态调整冗余率 (5%/15%/25%) |
| 自适应 Jitter Buffer | 基于抖动统计动态调整 (5-60ms) |
| 自适应码率 | RTCP 丢包反馈 → 发送端调整编码码率 |
| RTCP SR | 每秒一次，校准时钟漂移 |

**验收标准**：
- 用户 B 输入码后，用户 A 收到通知并可保持/让出
- 模拟网络抖动时 buffer 自动扩展，画面不卡顿
- 模拟 5% 丢包时 FEC 冗余自动升至 25%

**预计周期**：2 周

---

## v0.7 — Android TV 接收端

**目标**：第一个非桌面接收端上线。

| 模块 | 新增/变更 |
|------|----------|
| Android App | Kotlin + NDK (C++) |
| 网络 | Java NIO (DatagramChannel) |
| 解码 | MediaCodec 异步模式 → SurfaceView |
| 音频 | libopus NDK + Oboe LowLatency |
| 配对 UI | 全屏显示投屏码 + IP |
| NSD | Android NSD API 注册服务 |
| 热管理 | PowerManager thermal 回调 + 分级降级 |

**验收标准**：
- macOS/Windows 发送 → Android TV 接收，1080p@60fps 流畅
- 热降级：持续投屏 30 分钟后不因过热崩溃
- D-pad 遥控器可导航 UI

**预计周期**：3 周

---

## v0.8 — 桌面接收端 (投影仪场景)

**目标**：Mac Mini / Windows PC 作为投影仪接收端。

| 模块 | 新增/变更 |
|------|----------|
| 接收端二进制 | 复用发送端 Rust crate (transport/pairing/session) |
| macOS 解码渲染 | VideoToolbox + Metal 全屏 |
| Windows 解码渲染 | Media Foundation + D3D11 Waitable SwapChain |
| 音频 | CoreAudio 128 samples / WASAPI Shared 低延迟 |
| 投影仪适配 | 禁用 VSync, EDID 检测 + 用户确认 + 1080p 回退 |
| 分辨率匹配 | 能力协商上报 display 原生分辨率 |

**验收标准**：
- Mac Mini HDMI 连投影仪，接收 1080p@60fps 无撕裂
- Windows PC 接收端同等效果
- EDID 异常时正确回退到 1080p

**预计周期**：2 周

---

## v1.0 — 生产就绪

**目标**：稳定性、边界情况、打包分发。

| 模块 | 新增/变更 |
|------|----------|
| 稳定性 | 连续 8 小时投屏无崩溃/内存泄漏 |
| 错误恢复 | 网络断开自动重连，编码器异常自动重启 |
| 日志 | tracing 结构化日志，可导出诊断文件 |
| 打包 | macOS: .dmg, Windows: .msi, Android: .apk |
| 自动更新 | 版本检查 + 提示更新 (不强制) |
| 文档 | 用户使用指南 |

**验收标准**：
- 所有三种接收端 8 小时稳定性测试通过
- 安装包一键安装，无需开发环境
- WiFi 断连 → 重连后 5 秒内恢复投屏

**预计周期**：2 周
